領収書の内容を1件ずつ記録し、年／月単位で確認して Excel に出力します。同じ請求元の入力を「キロク」しておき、次回以降の入力を自動で補完するのが特徴です。

**インターネットに接続しません。** 経費・領収書ファイル・設定はすべて手元の PC の中だけに保存され、外部へ送信されることはありません。

対応 OS は **Windows** です（動作確認は Windows 11 / x64）。

## できること

### 入力アシスト（キロク）

請求元を選ぶと、その請求元で前回入力した**勘定科目・支払方法・按分率・税区分／税率・内容**を自動で埋めます。自動補完された項目にはバッジが付き、手で直すと外れます。候補はよく使う順（使用回数 → 最終利用日）に並びます。

### 消費税と事業按分

税込／税抜／非課税を選べ、税抜額・消費税額・税込額・経費計上額を入力しながら確認できます。事業按分率は勘定科目ごとに既定値を持たせられます。

按分の判断を税理士に任せたい場合は**「按分なし」**にチェックを入れます。按分率 100% で保存し、その旨を備考へ自動で追記するので、Excel を受け取った税理士がそのまま判断できます。チェックの状態は専用の列で保持しているため、備考の文言を消しても外れません。

### Excel 出力

一覧画面で指定した期間・絞り込みの条件そのままで出力します。明細1シートに合計行・オートフィルタ・ウィンドウ枠固定が付きます。列の構成は [`export-columns.ts`](src/shared/constants/export-columns.ts) の定義から生成されます。

### 領収書の添付

PDF・PNG・JPEG・GIF・WebP・HEIC を、1件につき最大10ファイル（1ファイル20MBまで）添付できます。ドラッグ&ドロップにも対応し、実体はアプリのデータ領域へ日付ごとにコピーされます。経費を削除すると添付ファイルも消えます。

保存時、**大きな JPEG・PNG は自動で縮小します**（長辺 2000px を上限に、形式は変えずに再エンコード）。スマートフォンで撮った領収書は 1/4〜1/10 程度になります。縮小しても小さくならない画像・小さいファイル・PDF はそのまま保存されます。

添付した画像・PDF は**「領収書」欄の添付一覧のすぐ下に中身が出ます**（経費入力・経費照会のどちらも同じ）。追加した直後はその1枚が表示され、複数ある場合は送りボタンで1枚ずつ切り替えられます。クリックすると別ウィンドウで大きく表示します（拡大縮小は Chromium 内蔵のビューアに任せています）。まだ保存していないファイルは選択元をそのまま読むので、添付したその場で中身を確認できます。HEIC は画面に表示できないため、その場合は「既定のアプリで開く」を案内します。

### スマートフォンの画像を取り込む

添付する方法は4つあります。スマホからの持ち込みには後ろの2つを使います。

| 方法 | 使いどころ |
| --- | --- |
| ファイルを追加 / ドラッグ&ドロップ | PC 上の場所がわかっているとき |
| **クリップボードから貼り付け（Ctrl+V）** | Windows「スマートフォン連携」でコピーしたスクショ、PC のスクショ（Win+Shift+S） |
| **取り込みフォルダから選ぶ** | Bluetooth 受信・iCloud・OneDrive・Google ドライブ経由で届いた画像 |

Ctrl+V はクリップボードに画像があるときだけ効くので、備考欄への文字の貼り付けは邪魔しません。

取り込みフォルダは設定画面の「領収書の取り込み元」で指定します。**Bluetooth の受信先やクラウドの同期フォルダをここに設定しておく**と、届いた画像がサムネイル付きで新しい順に並び、選ぶだけで添付できます。元のファイルはフォルダに残ります。

> **Bluetooth について**：アプリ自体は Bluetooth を扱いません。Windows 標準の Bluetooth ファイル受信で PC に保存し、その保存先を取り込みフォルダに指定してください。iPhone は Windows への Bluetooth 転送に対応していないため、クラウド同期フォルダを使ってください。

### バックアップ

起動時の自動バックアップ、世代数の上限、添付を含めるかどうかを設定できます。復元は確認ダイアログを挟み、**復元の直前に現在の状態を自動でバックアップ**してから実行します。

### 初期セットアップ

初めて起動したときは、利用規約への同意 → 3ステップのウィザード（プリセット・表示の設定 → 出力設定 → バックアップ先の設定）という順に進みます。

設定画面の「初期セットアップをやり直す」で最初からやり直せます。これは**初期化**なので、経費・領収書ファイル・請求元の記憶をすべて削除してからウィザードを開き直します（勘定科目・支払方法・各種設定は残ります）。取り消せない操作のため、**削除の直前に自動でバックアップを取得**します。元に戻したい場合は「バックアップ履歴」から復元してください。

## 利用規約と免責

初回起動時に利用規約が表示され、**同意しない限りアプリを使えません**。要点は次のとおりです。

1. **インターネットに接続しません。** データは PC の中だけに保存され、外部送信も利用状況の収集も行いません
2. **データの保管は利用者の責任です。** PC の故障・紛失・誤削除などで失われることがあります。バックアップの取得と別の場所への保管をお願いします
3. **無保証・免責。** 現状有姿で提供され、使用または使用不能によって生じた PC・データ・業務上の損害について作者は一切の責任を負いません
4. **税務上の判断は利用者と税理士が行ってください。** 算出される金額は入力値にもとづく計算結果にすぎず、税務上の正しさを保証するものではありません
5. **サポート・更新は保証しません。** 予告なく仕様変更・提供終了する場合があります

全文は [`terms.ts`](src/shared/constants/terms.ts) にあり、アプリの設定画面「利用規約を読み返す」からも確認できます。

規約を改定するときは `TERMS_VERSION` を上げてください。同意済みの利用者にも改めて同意を求める仕組みになっています。

## 動かす

必要なもの：Node.js 20 以降（開発環境では 24 で動作確認）、Windows。

```bash
npm install
```

`better-sqlite3` はネイティブモジュールですが、**ビルド済みバイナリを取得するため C++ のビルド環境は不要**です（[バージョンの制約](#バージョンの制約)を参照）。

```bash
npm start
```

配布用にまとめる場合：

```bash
npm run package
```

`out/Kiroku-win32-x64/Kiroku.exe` が生成されます。インストーラー（Squirrel）を作る場合は `npm run make` を使います。

## 画面

| 画面 | 役割 |
| --- | --- |
| 利用規約 | 初回起動時。同意するまで先へ進めない |
| 初期セットアップ | 初回起動時。プリセットと保存先を3ステップで決める |
| 経費入力 | 領収書1件を登録・編集する。入力アシストと計算プレビュー付き |
| 経費一覧 | 年／月・勘定科目・請求元・キーワードで絞り込み、合計と内訳を確認して Excel 出力する |
| 経費照会 | 一覧から開く。入力画面と同じフォームでその場で修正・削除でき、前後の領収書へも移動できる |
| 設定 | バックアップ、プリセット（勘定科目・支払方法）、出力設定、表示設定 |

一覧は「日付・勘定科目・請求元・金額（税込）・税区分／税率・操作」の6列で、**10件ごとのページング**です。横スクロールはせず、収まらない項目は「…」で省略してホバーで全文を表示します。行ごとの詳しい内訳（内容・支払方法・税抜額・消費税額・按分率・経費計上額・領収書）は経費照会画面で確認します。合計と勘定科目別の内訳は、表示中のページではなく**絞り込み全体**に対して集計されます。

照会画面から一覧に戻ると絞り込み条件と表示ページが復元されます。経費入力・設定へ移動したときは初期化されます。

照会画面には「前の領収書」「次の領収書」があり、**絞り込み結果の並び順のまま**ページをまたいで移動できます。CSV で明細だけ先に取り込み、あとから画像を順番に付けていく作業がこの画面だけで完結します。未保存のまま移動しようとすると確認を挟みます。

サイドメニューは開閉でき、状態は次回起動時に復元されます。非同期処理には範囲の異なるローディング表示を出し分けています（画面遷移＝コンテンツ領域、登録・出力・バックアップ＝全体、検索・期間切替＝一覧のみ）。ただし**前後の領収書への移動ではローディングを出しません**。同じ画面で対象を差し替えるだけなので毎回挟むとかえって待たされて見えるためで、読み込みが長引いたときだけ表示に切り替わります。

## データの保存場所

すべて `%APPDATA%\Kiroku`（`app.getPath('userData')`）配下に置かれます。

```
%APPDATA%\Kiroku\
  kiroku.db              SQLite データベース
  attachments\YYYY\MM\   添付した領収書の実体
  backups\               バックアップ世代（保存先は設定で変更可）
```

設定画面の「データの保存場所」から実際のパスを確認でき、フォルダを開けます。

### テスト

**提出資料の金額そのものを決める計算**を対象にしています。ここがずれても利用者は気づけないため、変更したら必ず実行してください。

| 対象 | 確認していること |
| --- | --- |
| [`money.ts`](src/shared/utils/money.ts) | 税込／税抜／非課税の計算、端数処理、按分。`税抜 + 消費税 = 税込` が常に成立すること、按分が税込額に対して行われること、100% 超の按分率が抑制されること |
| [`period.ts`](src/shared/utils/period.ts) | 月末・年末の取りこぼしがないこと。閏年（2024年）と100年単位の例外（1900年・2000年）を含む |
| [`allocation-note.ts`](src/shared/utils/allocation-note.ts) | 「按分なし」の定型文を備考へ足し引きしても、利用者が書いた文章を壊さないこと |

```bash
npm test
```

### 構成

3つのプロセスに加えて、型・定数・純粋関数を共有する `shared` を置いています。

```
src/
  main/        Electron メインプロセス
    config/      ウィンドウ設定・パス解決
    db/          接続、マイグレーション、リポジトリ
    services/    業務ロジック（検証・集計・Excel・バックアップ・添付）
    ipc/         ハンドラ登録
    windows/     ウィンドウ生成
  preload/     contextBridge で window.kiroku を公開
  renderer/    React（画面・共通コンポーネント・コンテキスト・フック）
    assets/      ロゴ（マーク／ワードマーク）
    screens/     terms / setup / entry / list / detail / settings
  shared/      types・constants・utils（Node にも DOM にも依存しない）
               *.test.ts が計算ロジックのテスト
```

### プロセス間のやり取り

レンダラは `window.kiroku` 以外の経路を持ちません（`contextIsolation: true` / `nodeIntegration: false` / `sandbox: true`）。すべての IPC は `ipcMain.handle` + `ipcRenderer.invoke` で、戻り値は次の形に統一しています。

```ts
type Result<T> = { ok: true; data: T } | { ok: false; error: AppError };
```

メイン側で例外を握り潰して `Result` に変換するため、レンダラに生の例外が漏れません。入力値の検証もメイン側のハンドラ入口で行います。

領収書の拡大表示だけは別ウィンドウ（[`attachment-window.ts`](src/main/windows/attachment-window.ts)）で、保存済みのファイルをそのまま読み込みます。表示専用なので preload を渡さず IPC の口を作らず、外部への遷移も塞いでいます。開くウィンドウは常に1つで、次の領収書を開くと中身が差し替わります。

### アイコンとロゴ

図案の原典は SVG 1つだけです。

- [`src/renderer/assets/logo-mark.svg`](src/renderer/assets/logo-mark.svg) — レシートのマーク。`npm run icons` がここに「キロク」の文字を足して PNG / ICO を生成します
- [`src/renderer/assets/logo-wordmark.svg`](src/renderer/assets/logo-wordmark.svg) — サイドメニュー用のワードマーク（濃い緑の背景に置く前提で白一色）

アイコン生成は Chromium に SVG を描画させて PNG を取り出し、ICO へ詰め直しています。画像変換ライブラリへの依存を増やさないため、Electron 上で実行する構成です。

## 設計方針

**値を直接書かない。** IPC チャンネル名、設定キーと既定値、プリセット初期値、Excel の列定義、UI 文言、パス、エラーコード、配色はすべて定数モジュールに集約しています。たとえばテーマ色は [`tokens.css`](src/renderer/styles/tokens.css) の CSS カスタムプロパティに集め、各コンポーネントの CSS は `var(--color-*)` を参照するだけです（例外は影やオーバーレイなど、透明度を重ねるための `rgba()` 指定のみ）。

配色を変えるときは `tokens.css` だけを直せば全画面に反映されます。逆にコンポーネント側へ色を直接書くと、この前提が崩れます。

**金額と率は整数で持つ。** 金額は円単位の整数、税率と按分率はベーシスポイント（`10000 = 100%`）で保持し、浮動小数の誤差を避けています。計算は [`money.ts`](src/shared/utils/money.ts) の純粋関数に集約し、画面のプレビューと Excel 出力で同じ関数を使うため結果がずれません。

**DB アクセスを閉じ込める。** SQL は `db/repositories` の中だけに置き、上位層はドライバを知りません。SQLite ドライバを差し替える必要が生じても影響範囲が限定されます。

**ローディングのちらつきを抑える。** 短時間で終わる処理でスピナーが一瞬だけ光るのを防ぐため、表示までの遅延（180ms）と最低表示時間（400ms）を設けています。制御は `useAsyncAction` に集約し、各画面が個別に `try/catch` と `isLoading` を書かずに済むようにしています。

## バージョンの制約

**Electron は 42.9.0 に固定しています。安易に上げないでください。**

`better-sqlite3` はネイティブモジュールのため、Electron の ABI に合ったビルド済みバイナリが必要です。npm に公開されている `better-sqlite3@12.11.1` が提供するのは Electron ABI 146（= Electron 42）までで、Electron 43（ABI 148）用のバイナリはありません。ビルド済みバイナリが無い場合はソースからのビルドになり、Visual Studio の C++ ビルド環境が必要になります。

上げるときは、先に対応するビルド済みバイナリの有無を確認してください。

```bash
node -e "console.log(require('node-abi').getAbi('43.0.0','electron'))"
```

出力された ABI に対して `better-sqlite3-v<version>-electron-v<abi>-win32-x64.tar.gz` が [リリース](https://github.com/WiseLibs/better-sqlite3/releases)にあり、かつその `<version>` が npm に公開されていれば上げられます。

なお npm 11 は既定でネイティブパッケージのインストールスクリプトをブロックします。承認済みの項目は `package.json` の `allowScripts` にあり、新しいネイティブ依存を追加した場合は `npm approve-scripts <パッケージ名>` が必要です。
